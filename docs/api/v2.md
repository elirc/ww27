# Customer Profiles API v2

Source of truth:
- Registry: `src/lib/versioning/version-registry.ts`
- Schemas: `src/lib/validation/customer-profile-schemas.ts`
- Mappers: `src/lib/versioning/customer-profile-contracts.ts`
- Routes: `src/app/api/platform/customer-profiles/route.ts` and `src/app/api/platform/customer-profiles/[profileId]/route.ts`

Lifecycle:
- Status: `CURRENT`
- Default version: `false`
- Rollout is controlled by `updateRollout()` in `src/services/api-version-service.ts`

Response shape:

```json
{
  "id": "profile_123",
  "externalReference": "acct_modern",
  "name": {
    "givenName": "Ada",
    "familyName": "Lovelace"
  },
  "email": "ada@example.com",
  "lifecycleState": "ACTIVE",
  "marketingOptIn": true,
  "createdAt": "2026-04-13T00:00:00.000Z"
}
```

Key compatibility rules:
- `toCanonicalCreateInput()` and `toCanonicalUpdateInput()` in `src/lib/versioning/customer-profile-contracts.ts` keep the service layer version-agnostic.
- `assertVersionAccess()` in `src/lib/versioning/version-rollout.ts` enforces percentage rollout and allowlists before the route reaches business logic.
- `getCreateProfileSchema("v2")` in `src/lib/validation/customer-profile-schemas.ts` is strict so extra fields do not silently drift into the contract.
