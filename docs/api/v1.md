# Customer Profiles API v1

Source of truth:
- Registry: `src/lib/versioning/version-registry.ts`
- Schemas: `src/lib/validation/customer-profile-schemas.ts`
- Mappers: `src/lib/versioning/customer-profile-contracts.ts`
- Routes: `src/app/api/platform/customer-profiles/route.ts` and `src/app/api/platform/customer-profiles/[profileId]/route.ts`

Lifecycle:
- Status: `DEPRECATED`
- Default version: `true`
- Sunset: `2026-12-31`

Response shape:

```json
{
  "id": "profile_123",
  "externalReference": "acct_legacy",
  "fullName": "Ada Lovelace",
  "email": "ada@example.com",
  "status": "active",
  "createdAt": "2026-04-13T00:00:00.000Z"
}
```

Key compatibility rules:
- `toCanonicalCreateInput()` in `src/lib/versioning/customer-profile-contracts.ts` splits `fullName` into `givenName` and `familyName`.
- `status: active|inactive` is migrated into the canonical lifecycle model before `CustomerProfileService` runs.
- `jsonWithVersionHeaders()` in `src/lib/http/api-response.ts` attaches `Deprecation`, `Warning`, and `Sunset` headers for every `v1` response.
